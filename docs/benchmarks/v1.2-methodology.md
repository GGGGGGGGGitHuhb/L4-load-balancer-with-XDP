# V1.2 UDP / XDP 性能测量方法

本方法固定 V1.2/S3 产品树 `2dd2c98283773925fe179bc58d9e93ceac148ab7`（`v1.2-s3`），只增加 Python 标准库测试工具。正式结果见 [性能报告](reports/v1.2-xdp.md)；吞吐不是阶段通过的速度门槛。每角色独立执行 126 次，不混合 Builder 与 Reviewer 数据。

## 拓扑与可比边界

每个 run 创建独立匿名 mount/net/PID namespace，内部 LB、client 和两个 backend 网络空间都归该 run 所有。接口 MTU 为 1500。16 个 client socket 使用 `198.18.0.1:40000..40015`，业务 VIP 为 `198.19.0.100:39001`，backend 探测端点为 `198.20.{0,1}.2:39009`。两个后端进程运行同一份 Python echo 代码，分别记录业务收到/回复与探测次数。

| 路径 | 请求 | 回复 | 调度与成本边界 |
| --- | --- | --- | --- |
| direct | client → backend0 的直连 veth → VIP | backend0 VIP → client 直连 veth | 仅参考发生器/单后端能力 |
| proxy | client → LB 用户态 UDP proxy → backend 地址 | backend → proxy → client，源为 VIP | round_robin 按 flow，双向经过 proxy |
| static-generic/native | client → LB XDP v2 → backend VIP | backend VIP → client 独立直连 veth | 五元组 hash，单向 L2 改写 |
| runtime-generic/native | client → LB XDP v3 → backend VIP | 同 static DSR | 先验证两个 Healthy 与实际 active=2，再 warmup |

正反路径、源地址和 flow 生命周期不同，所以 direct 不能称与 proxy/DSR 等价；proxy 与 DSR 的差值也不是单一系统调用节约。veth 发送 checksum offload 关闭，native 模式在两个接收 peer 安装固定 S3 XDP_PASS 对象以启用 veth NAPI。原始包保存各 namespace 的地址、路由、邻居、接口、offload、PASS 辅助状态、启动命令和实际 VIP 回包样例。所有路由及 rp_filter 变更只作用于本次拥有的 namespace。

## 固定矩阵与时钟

- 稳态：6 路径 × payload 64/1024 字节 × 总目标速率 1000/10000/50000 pps × 3 次重复，共 108。payload 包括身份头与末尾 backend 标记。
- 控制面：generic/native × steady/unchanged/reorder × 3 次重复，共 18；payload 256、10000 pps。测量第 2/4/6/8 秒发 HUP；reorder 每次交换同一对后端顺序并要求 generation 前进，unchanged 不得前进。
- 每次 warmup 2s，开放节拍发送窗口 10s，超时/排空上限 1s。总目标在 16 个 socket 之间按 sequence 轮转分配；错过时隙不补发 burst，记录 missed_slots。
- 同一 payload/rate 的路径顺序按重复轮换 0/2/4 位；控制场景按重复轮换。精确 manifest 与逐次结果一一对应。正式测量串行，不同时运行本任务构建/回归/其他测量，保留默认 CPU affinity。
- 每 run 启动准备 ≤15s，外层 watchdog 默认 45s，TERM 后有界 KILL/reap。输出目录必须不存在；失败目录保留。工具身份改变后，受影响正式整套数据重跑，不选择最好三次。

## 计数、延迟与 CPU

业务报文含固定 magic、128-bit run nonce、phase、client、sequence。回包必须来自目标 VIP/端口、归属于原 client 且 payload 完整；末尾一个字节记录后端编号。warmup 与 measurement phase 分离。重复、迟到单列，损坏或跨 socket 身份错误令 run 无效。

`target = attempted + missed_slots`，`attempted = sent + send_errors`，`sent = unique_received + timeout`。pps 使用发送窗口内请求得到的唯一及时有效回复数 / 10；goodput Mbit/s = 此数 × payload × 8 / 10 / 10^6。loss = `(sent - unique_received) / sent`，分母 0 为 null。漏发时隙不是网络丢包，排空不延长分母。逐秒数据按请求发送时间归桶，所以最后一秒的及时回复可在排空时抵达。

RTT 使用 monotonic_ns，sequence stride 固定为 100，保留 client/seq/send_ns/receive_ns/rtt_ns。nearest-rank p50/p95/p99 单位微秒；成功样本少于 100 时 p99=null 并标记不足。只采成功请求有幸存者偏差，须与 loss 一起阅读；三次分别计算分位，不混池。计数原始行、每秒行、后端计数、RTT 与资源原始行都在公开包内。

每 50ms 采集 generator、两个业务/探测 backend 及 proxy/loader 的 PID、starttime、utime/stime、RSS/fd，保存窗口前后屏障；CPU% 为 jiffy 差 / SC_CLK_TCK / 实际采样间隔 ×100，以一个逻辑核为 100%。采样包含屏障附近的小段额外时间，实际间隔在 JSON 中给出。RSS/fd 是采样峰值。direct 无产品进程，product_cpu=null；进程消失、PID 重用、采样失败都不能当 0。

同时保存全机/逐 CPU `/proc/stat` 与 NET_RX/NET_TX softirq 累积项。guest 已包含在 user/nice，不能重复相加；softirq 是 busy 的子集。XDP 数据面运行在内核，**loader CPU 不是 XDP 数据面 CPU**。全机增量含本 WSL VM 其他任务与测量工具，不能将其或减去 direct 的差值称精确 BPF CPU。额外 3s 空闲窗口仅说明背景，不机械扣减。

控制行由独立读线程持续消费，保存接收 monotonic 时间；HUP 保存计划/实际 dispatch、配置文本及 SHA、确认原始行、实际 generation/active/MAC 顺序。HUP 到观测确认行的时间称“用户可见确认延迟”，包含日志、采样和调度成本，不能称内核提交耗时。steady 包含常开探测；unchanged/reorder 差不能完全分离某个健康算法或系统调用。

## 可执行命令

在仓库根目录使用不存在的角色工作目录，依赖为已有 CMake、C++、Clang BPF、libbpf、iproute2、ethtool 和 Python3；不安装新包。以下例子在本机原生 WSL 执行，`libbpf-prefix` 为已有只读依赖。Reviewer 改用自己的 `reviewer` 根。

```sh
work="$PWD/.stage-tmp/v1.2-s4/builder-reproduce"
mkdir -p "$work/tmp" "$work/cache"
export TMPDIR="$work/tmp" TMP="$work/tmp" TEMP="$work/tmp"
export XDG_CACHE_HOME="$work/cache" PYTHONPYCACHEPREFIX="$work/cache/py"
python3 tests/v12_benchmark.py build --directory "$work/products" \
  --libbpf-prefix "$PWD/.stage-tmp/v1.1-s2/deps/root/usr"
python3 tests/v12_benchmark_test.py
```

`build` 只读导出固定 S3 Git 树，从它分别构建 ON/OFF Release、BUILD_TESTING=OFF，关闭 Python package 查找。产品 provenance 与工作树新工具 SHA 分离；BPF debug 路径可令不同角色的对象字节不同，各自记录实际 SHA。

短真实六路径与正式命令只相差 `--short`。WSL root 入口是明确权限边界，应通过本机允许的窄权限方式执行；下面进程只修改自有匿名 namespace。

```sh
/mnt/c/Windows/system32/wsl.exe --distribution Ubuntu --user root --cd "$PWD" --exec \
  env TMPDIR="$TMPDIR" TMP="$TMP" TEMP="$TEMP" XDG_CACHE_HOME="$XDG_CACHE_HOME" \
  PYTHONPYCACHEPREFIX="$PYTHONPYCACHEPREFIX" python3 tests/v12_benchmark.py run \
  --short --product "$work/products/product.json" --directory "$work/short"
# 正式 126 次：移除 --short，使用新的 --directory "$work/formal"。
# 控制短测：另加 --paths runtime-native --scene reorder（或 unchanged）。
# 最高负载短测：另加 --short-rate 50000 --short-payload 1024。
/mnt/c/Windows/system32/wsl.exe --distribution Ubuntu --user root --cd "$PWD" --exec \
  env TMPDIR="$TMPDIR" TMP="$TMP" TEMP="$TEMP" XDG_CACHE_HOME="$XDG_CACHE_HOME" \
  PYTHONPYCACHEPREFIX="$PYTHONPYCACHEPREFIX" python3 tests/v12_benchmark_faults.py \
  --product "$work/products/product.json" --directory "$work/faults"
```

短测默认 .2s warmup、1s 发送；控制短测为 6s、五等分的四次事件，避免重载节流混入未完成请求。短测不属于正式 126 数据。faults 精确检查损坏/跨 client、错误 binary 身份、ready 子进程退出、采样错误、流量开始后写错误、watchdog、外层 SIGTERM；最后核验 owned PID 回收与宿主网络/挂载不变。

## 离线重算与失败保存

```sh
sha256sum -c docs/benchmarks/reports/v1.2-xdp.raw.sha256
python3 tests/v12_benchmark.py validate docs/benchmarks/reports/v1.2-xdp.raw.json.gz \
  --summary docs/benchmarks/reports/v1.2-xdp.json
python3 tests/v12_benchmark.py recompute docs/benchmarks/reports/v1.2-xdp.raw.json.gz \
  --summary "$TMPDIR/recomputed.json"
python3 tests/v12_benchmark_test.py --package docs/benchmarks/reports/v1.2-xdp.raw.json.gz
```

重算仅需测试侧 Python 文件和公开 gzip JSON，不读取包内记录的本机绝对路径、Git 对象、binary 或网络。gzip 作为数据读取，不解压路径；单 run 上限 8MiB、整个公开未压缩包上限 128MiB。package/run SHA 检查以外还检查计数恒等式、时钟、PID、RTT、矩阵完整性、原始控制确认关联；负向会重算篡改后的 checksum，仍要求语义错误被拒绝。所有汇总 JSON 由同一纯 reducer 产生，正式报告引用逐格结果，三次只报告中位/最小/最大及逐次值，不做统计显著性或普适加速断言。

性能结论仅限本机 WSL2/veth。Python 发生器/echo、VM 调度、背景负载、无物理 NIC/offload 的拓扑可能决定观测上限；未达到目标或丢包是有效观测，不能删去。此方法不验证物理 NIC、云机、线速、生产应用健康、连接保持或 draining。
