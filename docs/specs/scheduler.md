# 调度策略规格

适用 V0.2/S1，策略唯一值 `round_robin`，缺省行为与 V0.1 固定轮询一致。当前只服务 TCP；UDP 仅支持配置校验。

## 模型与接口

- 单 listener 对应一个按配置顺序排列的静态 backend pool，以及一个独立 scheduler。无命名池、多 listener、权重、健康状态或全局 cursor。
- `core/scheduler.h` 定义带虚析构的 `Scheduler` 与 `next()`；`make_scheduler(SchedulerKind, pool_size)` 返回独占实例。`RoundRobin` 实现接口。
- 空 pool 抛 `std::invalid_argument`；未知策略枚举防御性抛同类异常，不静默回退。配置层限制 1..256 个后端，策略可处理正的 `size_t` 池大小。
- 初始索引为 0，依次到 N−1 后返回 0；N=1 恒为 0。比较池尾再递增，避免累计次数溢出。结果始终小于固定池大小。
- 算法 O(1)，状态 O(1)，`next()` 不分配；无 socket、日志、探活、全局可变状态。实例之间互不干扰，服务重启重新从 0 开始。当前单线程，不提供并发调用契约。

## TCP 数据流与生命周期

- 控制层先验证协议，再按配置策略创建 scheduler，以选择回调提供后端索引；scheduler 由控制层持有，其生命周期覆盖整个同步 `net::run`。
- reactor 不知道策略名称或协议解析。每个已接受且进入会话建立的连接调用选择回调一次；容量等早期拒绝不消耗轮询位置。
- 后端连接失败仍消耗这次选择，不回滚、不重试、不自动跳过；下一新会话继续下一位置。回包、读写、半关闭、资源回收不推进策略。
- UDP 分派在所有网络资源创建前拒绝，TCP 入口也防御非 TCP 直调。真实 UDP 转发留到 S2。

## 验证边界

- `v02_scheduler_unit` 通过统一接口验证 N=1/3/256、多轮顺序、交错独立实例、重建归零、空池及未知枚举拒绝和两个控制入口防御；运行期检查在 Release 保持有效。
- `config_unit` 和 `cli_integration` 验证省略、乱序、严格错误、默认兼容与 UDP 输出。
- `s3_product_smoke` 同时运行旧配置和显式配置：测试后端以不同 XOR 标记回包，逐字节比较 A/B/A/B；失败/B/失败/B 检查失败无数据和随后精确 B 字节。后端标记仅为测试 fixture，生产转发不修改字节。
- UDP check/run 测试包含空闲和 TCP/UDP 同时占用目标端口、后端连接队列检查和退出后重绑；源码及无 socket 权限下的控制入口测试确认拒绝位置。现有半关闭、背压和资源回收测试保留。
