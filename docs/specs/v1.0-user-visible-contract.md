# V1.0/S1 用户态行为契约

基线 V1.0-S1-D1。本文冻结现有用户可观察行为；阶段验收状态由 Leader 收尾记录，不表示 V1.0 已发布。内部类、测试注入接口、日志中的动态 ID 不属稳定 API。

## 配置及入口

六键及全部格式、端点范围、文件类型、65536 字节上限、首错规则继承 [配置规格](config-schema.md)。`listen` 必填一次，无默认；`backend` 必填 1..256 个不同端点且保持顺序，无默认。可选键默认分别是 `protocol=tcp`、`scheduler=round_robin`、`health_check=off`、`metrics=off`。唯一可选值分别是 tcp/udp、round_robin、off/tcp_connect、off/stderr；大小写敏感，重复同值也拒绝。无环境覆盖、默认文件搜索、写回或自动迁移。

- `--help` 独占入口：退出 0，stdout 帮助并以换行结束，stderr 空，不读配置。
- `--check-config <path>`：仅静态检查，不能推断端点可达性；不建 socket、不探活。退出 0，stderr 空，stdout 精确为 `配置有效：TCP，后端数量=N\n` 或 UDP 对应格式；此处 `\n` 表示一个 LF。
- 参数错误：退出 2，stdout 空，stderr 用法错误及 `--help` 提示。
- 配置/文件错误：退出 1，stdout 空，stderr 配置错误类别及原因。字段错误保留首错行号，缺必填字段保留 EOF/下一行号；不回显原始配置内容，文件错误可以带用户给定路径。
- `--run <path>`：同一加载入口；正常停止退出 0，启动/运行异常退出 1。强杀或信号默认终止仍遵循 POSIX，不包装成正常退出。

## 运行、输出与兼容性

- ready 精确为 `TCP 服务已启动：<配置IPv4>:<端口>\n` 或 UDP 对应格式，stdout 输出。它仅表示监听就绪，不代表 backend 可达或 Healthy；启动失败不得有 ready。原 check/ready 消费工具保持兼容。
- 生命周期、健康、业务诊断和指标写 stderr。保留操作/错误类别、适用的行号和 errno 信息；不承诺内部 session/flow ID、时间、系统 strerror、人类说明文字跨运行逐字一致，不为语言统一改写 reason 日志。
- metrics 保持 `metrics ` 前缀、schema=1、字段类型/顺序/计数含义，详见 [metrics](metrics.md)。stdout ready 在 ready 快照之前；periodic 按原周期；final/error 在资源清理之后。stderr 混合业务日志，整体不是 JSONL。off 无采集和指标输出。
- [TCP](tcp-forwarding-semantics.md) 双向字节流、背压、半关闭、超时/容量、固定轮询且连接失败不换后端重试；[UDP](udp-flow-table.md) flow key/固定绑定、60 秒 idle、容量、尽力报文转发、零长和源过滤；[scheduler](scheduler.md) 选择推进规则均保持。
- [健康检查](health-check.md) 默认 off；tcp_connect 仅 TCP 握手代理信号，Unknown 初态，连续 2 成功/3 失败。无 Healthy 拒绝新业务，旧绑定不迁移。UDP **仅在启用 tcp_connect 时**需要同 IP/端口且代表 UDP 服务的 TCP 健康端点。
- [有界停止](../runbooks/local-v0.4-lifecycle-validation.md)：TCP 固定 1 秒 draining 截止，仅尝试发送用户态 pending，不接收新流量，不保证内核/网络在途数据送达；UDP 关闭 flows，无排空保证。
- 同步 stdout/stderr 可能阻塞。1 秒截止不是堵塞输出下绝对进程退出时限。metrics 输出失败后禁用、可能半行，SIGPIPE/强杀可能无尾快照；不承诺非阻塞或可靠落盘。

## 本阶段文案变化与保护

旧 help 的“UDP 启用需……”改为“UDP 仅在启用 health_check=tcp_connect 时需……”，同时补充 ready 和停止边界。config-schema 同步该条件。既有 CLI 帮助断言依赖旧词句，已同步；仓库检索未发现其他工具依赖旧句。成功格式、配置示例、数据面、metrics schema 未变。

- `config_unit`、`cli_integration`：六键默认/范围、重复未知/大小写、文件类型/大小、旧示例、精确成功文本、错误流/行号/EOF与帮助。
- `v10_user_visible_contract`：8 种可选组合在被占监听地址/不可达 backend 下静态成功且哈希不变；TCP/UDP 启动失败无 ready、精确 ready、正常停止、off 无指标；自有 PID/fd/端口/临时配置清理。
- `v03_health_*`、`v03_metrics_*`、`v03_system_*`：预热/无健康拒绝、旧绑定/独立 payload、计数及尾快照；健康产品用例额外精确检查 ready。
- `v10_fixture_pair`：测试夹具成对保留 UDP/TCP 端口，确定性覆盖首冲突后成功、16次占用耗尽、其他错误立即传播和 socket/thread 清理，不改变产品行为。
- 原 TCP/UDP（含长 expiry）和 V0.4 lifecycle 回归继续保护数据面。Debug 快速、Release 完整及 Production 构建结果见阶段角色报告；新增关键断言须用至少两项受控负向变异自证。
